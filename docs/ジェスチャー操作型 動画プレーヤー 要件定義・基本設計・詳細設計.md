# ジェスチャー操作型 動画プレーヤー 要件定義・基本設計・詳細設計

## 0. この文書について

スポーツ観戦や分析を目的とした動画視聴の際、「N秒スキップ」と「速度変更」が簡単なジェスチャーのみでできることは非常に重要だと考えている。筆者の需要として、iPhoneのSafari等で動作し、再生中の画面のタップとスワイプだけでそれらができる動画プレーヤーを、Webコンポーネントとして作るための要件と設計をまとめた。ジェスチャーの判定ルールを中心に定義し、その機能を梱包したプレイヤーをWebコンポーネントとして提供する。

- 第1部 要件定義：何を満たすか
- 第2部 基本設計：画面・操作・公開APIの外形
- 第3部 詳細設計：判定ロジック・数値・ビルド・テスト

### 前提と未確定事項（要確認）

## 第1部 要件定義

### 1.1 スコープ

| 区分 | 内容 |
| --- | --- |
| 対象 | 端末内の動画ファイルの読み込みと再生、ジェスチャー操作、YouTube風の操作パネル、Webコンポーネントとしてのビルド |
| 対象外（今回） | ネット上の動画URLのストリーミング、プレイリスト、字幕、ABリピート、コマ送り、オフライン対応、ネイティブアプリ化 |

### 1.2 機能要件

| ID | 要件 | 内容 |
| --- | --- | --- |
| FR-01 | 動画の読み込み | ファイル選択で、写真ライブラリまたはファイルアプリの動画を1本読み込む。サーバーへの送信はしない |
| FR-02 | 再生・停止 | 中央領域のシングルタップ、または操作パネルのボタンで切り替える |
| FR-03 | 巻き戻し | 左領域（左端〜37%）のダブルタップで、基準10秒を戻す |
| FR-04 | 送り | 右領域（63%〜右端）のダブルタップで、基準10秒を進める |
| FR-05 | 速度連動スキップ | 等倍より遅いときは、スキップ秒数を「10秒×再生速度」にする（0.25倍なら2.5秒） |
| FR-06 | ダブルタップの判定 | 1回目のタップから0.2秒以内に同じ領域をタップしたらダブルタップとする。0.2秒を過ぎたらシングルタップとして処理する |
| FR-07 | 連続スキップ | ダブルタップ後に同じ側を続けてタップすると、1回分ずつ追加でスキップする（Q5） |
| FR-08 | 速度変更 | 動画上を縦にスワイプして速度を変える。上で速く、下で遅く。指を動かしている間も速度が即座に変わり、現在の倍率を大きく表示する |
| FR-09 | 操作パネル | YouTube風のUI。再生ボタン、シークバー、経過時間／総時間、速度表示、ファイル選択、全画面ボタンを持つ。再生中は3秒で自動的に隠す |
| FR-10 | 操作の反応表示 | スキップ時はその側に波紋と「−2.5秒」のような秒数を、速度変更時は中央に倍率を表示する |
| FR-11 | Webコンポーネント | カスタム要素タグ1つで他のページに組み込める。属性で数値を変更でき、イベントで状態を取得できる |

### 1.3 非機能要件

| ID | 分類 | 内容 |
| --- | --- | --- |
| NFR-01 | 応答性 | ダブルタップの2回目を離してから50ミリ秒以内にスキップする。速度変更は次の画面更新で反映する |
| NFR-02 | シングルタップの遅延 | 判定のため、0.2秒待ってから実行する。仕様上の遅延として許容する |
| NFR-03 | プライバシー | 動画は端末の外に出さない。通信も外部ライブラリの読み込みも行わない |
| NFR-04 | 誤操作の防止 | 動画上の操作で、画面の拡大・スクロール・テキスト選択・長押しメニューが起きないようにする |
| NFR-05 | 依存関係 | 実行時に外部ライブラリを使わない。配布物はJavaScriptファイル1つ |
| NFR-06 | メモリ | 別の動画を読み込んだときや要素が削除されたときに、古い動画の参照を解放する |

### 1.4 制約

- **iPhoneの全画面表示**：iPhoneのSafariでは、動画以外の要素を全画面にする標準の仕組み（Fullscreen API）が使えません。2024年2月のiOS 17.4ベータで一度無効化され、2025年時点でも未対応という報告があります（[Apple Developer Forums](https://developer.apple.com/forums/thread/133248?page=2)、iOS 26での状況は要確認）。動画だけを全画面にするとOS標準のプレーヤーに切り替わり、独自のジェスチャーが効かなくなります。そのため、画面いっぱいに広げる疑似全画面で対応します。
- **再生できる形式**：Safariが対応する形式（MP4・MOV、H.264・HEVC）に限ります。MKVは再生できません。WebMの対応範囲は要確認です。
- **スローの下限**：0.1倍など極端な低速で、音声や映像がどうなるかはブラウザによって異なります。実機で確認が必要です（要確認）。
- **振動による反応**：iPhoneのSafariでは、Webページから端末を振動させられません（要確認）。速度が1倍に戻ったことは、画面表示だけで知らせます。

## 第2部 基本設計

### 2.1 全体構成

プレーヤーはカスタム要素 `<sports-video-player>` 1つです。要素の中は外のページのスタイルの影響を受けないように隔離し（Shadow DOM）、次の4層を下から重ねます。

1. 動画層：`<video playsinline>`。OS標準の操作パネルは使わない
2. ジェスチャー層：動画全体を覆う透明な層。タップとスワイプをすべてここで受ける
3. 反応表示層：スキップ時の波紋と秒数、速度変更時の倍率を出す。タップは受けない
4. 操作パネル層：上部バー、中央の再生ボタン、下部バー。表示中はボタン部分だけタップを受ける

内部は、画面を組み立てる本体、タップとスワイプを判定する部品、スキップ秒数と速度を計算する部品に分けます。判定と計算は画面から切り離し、単体でテストできるようにします。

### 2.2 画面とタップ領域

動画の横幅に対する割合で、3つの領域に分けます。領域は表示中の動画枠の幅で計算するので、縦向き・横向きで割合は変わりません。操作パネルの表示中は、下部バー（下端から56px）をジェスチャーの対象外にします。

&#91;embedded content: タップ領域 · 3領域と下部バー\]

| 領域 | 範囲（左端からの割合） | シングルタップ | ダブルタップ |
| --- | --- | --- | --- |
| 左 | 0%以上、37%未満 | 操作パネルの表示切り替え | 巻き戻し |
| 中央 | 37%以上、63%以下 | 再生・停止の切り替え | 何もしない |
| 右 | 63%超、100%以下 | 操作パネルの表示切り替え | 送り |

### 2.3 ジェスチャー一覧

| 操作 | 判定条件（要約） | 動作 |
| --- | --- | --- |
| シングルタップ | 指を離してから0.2秒、次のタップがない | 2.2の表のとおり |
| ダブルタップ | 1回目を離してから0.2秒以内に、同じ領域で再びタップ | 左：巻き戻し、右：送り |
| 連続タップ | ダブルタップ後、0.5秒以内に同じ側をタップ | 1回分を追加でスキップ。表示は合計秒数（例：−7.5秒） |
| 縦スワイプ | 指が縦に12px以上動き、縦の動きが横の1.5倍以上 | 速度を段階的に変える。上で速く、下で遅く |
| 横スワイプ | 指が横に12px以上動き、縦スワイプの条件を満たさない | 何もしない（将来のシーク操作用に空けておく） |
| 長押し | 指を置いたまま動かさず0.3秒を超える | 何もしない。タップにも数えない |

スワイプだと判定した時点で、その操作はタップに数えません。待ち状態のシングルタップがあれば、それはそのまま0.2秒後に実行します。

### 2.4 速度とスキップ秒数

速度は次の9段階から選びます。縦スワイプで32px動くごとに1段階変わり、端の段階で止まります。速度を変えても、再生中か停止中かは変わりません。

| 速度 | 0.1 | 0.25 | 0.5 | 0.75 | 1 | 1.25 | 1.5 | 1.75 | 2 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| スキップ秒数 | 1 | 2.5 | 5 | 7.5 | 10 | 10 | 10 | 10 | 10 |

### 2.5 操作パネル（YouTube風UI）

- **上部バー**：ファイル名、ファイル選択ボタン
- **中央**：再生／停止ボタン（直径56px）。左右にスキップボタンは置かない（ダブルタップとの誤操作を避けるため）
- **下部バー**：シークバー、「経過時間 / 総時間」、速度（例：0.25x。タップで速度一覧を開く）、全画面ボタン
- **自動で隠す条件**：再生中に3秒操作がないとき。停止中は表示したままにする
- **速度が1倍以外のとき**：操作パネルを隠していても、右上に倍率を小さく表示し続ける
- **見た目**：動画の上下に黒のグラデーションを敷き、白のアイコンを置く。表示・非表示は0.2秒でフェードさせる

### 2.6 公開API（Webコンポーネント）

使う側はJavaScriptファイルを1つ読み込み、タグを置くだけで使えます。

```html
<script type="module" src="sports-video-player.js"></script>
<sports-video-player file-picker></sports-video-player>
```

属性・メソッド・イベントの定義は第3部 3.5にまとめます。

### 3.2 ジェスチャー判定

判定は2段階です。まず指の動きを分類し（pointer-tracker）、タップだけを次の分類（tap-classifier）に渡します。

**段階1：指の動きの分類**（指を1本置いてから離すまで）

| 状態 | 条件 | 次の状態と処理 |
| --- | --- | --- |
| 待機 | 指を置く（pointerdown、最初の指のみ） | 押下中へ。開始位置・時刻・領域を記録し、指の追跡を確保する（setPointerCapture） |
| 押下中 | 縦の移動が12px以上、かつ縦が横の1.5倍以上 | 縦スワイプ中へ。開始時の速度段階を記録し、倍率表示を出す |
| 押下中 | 横の移動が12px以上 | 横スワイプ中へ（何もしない） |
| 押下中 | 動かさず0.3秒を超える | 長押し中へ（何もしない） |
| 押下中 | 離す（0.3秒以内、移動10px未満） | 待機へ。「タップ（領域）」を段階2に渡す |
| 縦スワイプ中 | 指を動かす | 速度段階を計算し、変わったら即座に反映する（3.4） |
| 縦スワイプ中 | 離す | 待機へ。倍率表示を0.6秒後に消す |
| どの状態でも | 2本目の指を置く、またはpointercancel | 待機へ。その操作は破棄し、速度はその時点の値を保つ |

**段階2：タップの分類**

&#91;embedded content: タップ分類 · 3状態\]

| 状態 | 来たタップ | 処理 |
| --- | --- | --- |
| なし | 任意の領域 | 2回目待ちへ。200msのタイマーを開始。時間切れでシングルタップを実行し、「なし」へ |
| 2回目待ち（左または右） | 同じ領域 | タイマーを止め、スキップを実行。連続中へ（500msのタイマー） |
| 2回目待ち（中央） | 中央 | タイマーを止め、何もしない（Q4）。「なし」へ |
| 2回目待ち | 別の領域 | 1回目のシングルタップをすぐ実行し、今回のタップで新たに2回目待ちへ |
| 連続中 | 同じ側 | すぐにスキップを追加し、500msのタイマーをやり直す |
| 連続中 | 別の領域 | 連続を終え、今回のタップで新たに2回目待ちへ |

【重要】200msは「1回目を離した時刻」から「2回目の指を置いた時刻」までで測ります。2回目の指を置いた時点でタイマーを保留し、離したときにタップかどうかを確定します。その指がスワイプや長押しだった場合は、保留していたシングルタップをその時点で実行します。こうすると、素早いダブルタップが「停止→再生」と誤判定されることを防げます。

### 3.4 計算式

スキップ秒数（S：基準秒数、r：再生速度）。等倍以上は基準秒数のままです。

```latex
\Delta = S \times \min(r,\ 1)
```

移動後の再生位置（t：現在位置、d：総時間、巻き戻しは−、送りは＋）。動画の先頭と末尾で止めます。

```latex
t' = \min\left(\max\left(t \pm \Delta,\ 0\right),\ d\right)
```

縦スワイプ中の速度段階（i₀：開始時の段階番号、Δy：開始位置からの縦の移動で下向きが正、p：1段階あたりの移動量、n：段階の数）。上に動かすと速くなります。

```latex
i = \min\left(\max\left(i_0 - \operatorname{trunc}\left(\frac{\Delta y}{p}\right),\ 0\right),\ n-1\right)
```

- 表示する秒数は小数点以下1桁までとし、末尾の0は省きます（2.5秒、10秒）
- 連続タップ時は、実際に動いた秒数の合計を表示します。先頭・末尾で止まった分は含めません
- 動画の情報（総時間）を読み込む前のスキップは無視します
- 速度は `video.playbackRate` に設定します。音の高さは変えません（`preservesPitch = true`）。Safariが0.1倍を受け付けない場合は、受け付けた最小の段階を下限にします（要確認）

### 3.5 公開API

**属性**（3.3の数値のほか）

| 属性 | 型 | 既定値 | 説明 |

| rate | `number`（読み書き） | 再生速度。段階にない値は一番近い段階に合わせる |
| currentTime | `number`（読み書き） | 再生位置（秒） |
| duration / paused | `number` / `boolean`（読み取り専用） | 総時間、停止中かどうか |

**イベント**（CustomEvent。親要素へ伝わり、Shadow DOMの外でも受け取れる）

| イベント名 | detail | 発生するとき |
| --- | --- | --- |
| gvp-load | `{ name, duration }` | 動画の情報を読み込んだ |

| gvp-ratechange | `{ rate, source }` | 速度が変わった（sourceは swipe / menu / api） |
| gvp-playstate | `{ paused }` | 再生・停止が切り替わった |
| gvp-error | `{ code, message }` | 読み込みや再生に失敗した（非対応形式など） |

### 3.6 iPhone向けの実装上の注意

- ジェスチャー層には `touch-action: none` を指定し、ブラウザのダブルタップ拡大とスクロールを止める。あわせて `user-select: none`、`-webkit-touch-callout: none`、`-webkit-tap-highlight-color: transparent` を指定する
- 指の操作はPointer Eventsで受ける。マウスでも同じ処理で動く
- `<video>` には `playsinline` を付け、`controls` は付けない。付けないと、再生したとたんにOS標準の全画面プレーヤーに切り替わる
- 全画面ボタン：`Element.requestFullscreen` が使える環境（PC、iPad）ではそれを使う。使えない環境（iPhone）では `fullscreen` 属性を付け、`position: fixed; inset: 0; height: 100dvh` で画面いっぱいに広げる。画面上部の切り欠きなどには `env(safe-area-inset-*)` で余白を取る
- ホーム画面に追加して使う前提で、デモページには `apple-mobile-web-app-capable` などの設定を入れる（要確認：現行iOSでの推奨設定）
- 動画の参照（`URL.createObjectURL` で作ったもの）は、次の動画を読み込むときと要素が削除されるとき（`disconnectedCallback`）に解放する
- タイマーは `performance.now()` を基準にし、イベントの `timeStamp` で間隔を測る

### 3.7 ビルド構成

- 言語はTypeScript、ビルドはViteのライブラリモード。実行時に使うライブラリはなし
- 出力は2つ：`dist/sports-video-player.js`（ESモジュール）と `dist/sports-video-player.iife.js`（普通の `<script>` 用）
- CSSは文字列として取り込み（`?inline`）、Shadow DOMに適用する。アイコンはコード内にSVGで埋め込む。配布物はJavaScriptファイル1つになる
- コマンド：`npm run dev`（デモを起動。`--host` で同じWi-FiのiPhoneから開ける）、`npm run build`、`npm test`
